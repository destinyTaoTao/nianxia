## 执行顺序与验收

- [x] R1 转写重试：Notebook.transcribe保持公开interface；把running写入纳入同一try/finally，失败状态写回不得掩盖原始错误。新增test/transcription_recovery_test.dart，真实SQLite触发器让running失败后重试成功、failed写回失败保留原错误和音频；保留CAS/关闭/迟到写回测试。
- [x] R2 默认录音设备确认：DeviceMicrophone.cancel不能依赖锁定SDK未等待native回执的cancel实现；流式采集用真实停止确认。CaptureController在stop/cancel/close失败、尚未结束时保留设备占用及可重试恢复路径，跨页面/新录音不得绕过；状态流onError走解释性结束并保存有效PCM。确切私有接口在实现前以设备回执回归收窄，不增加第三个录音业务所有者。
- [x] R3 查询临时清理：_start/_finish/_release各路径的文件清理失败不能跳过状态与资源收尾；仍报告未清理，不谎称删除/保留成功。与R2区分设备未确认和仅文件清理失败，建立目录删除故障回归；dispose不得产生未处理Future。
- [x] R4 有界任务历史：LocalJobStore在已知v1内有界修剪无效旧修订/代际及已完成记录，保留当前失败与尝试上限语义；临时SQLite页数预算耗尽后可恢复认领，不清未知未来版本、不碰源库、不重放云端。由当前源状态决定是否仍需任务。
- [x] R5 追加失败诚实状态：父在开始前消失、尚无draft/nativeId时不显示“音频仍保留”或独立保存入口，提供返回/文字可行路径；已有真实片段的主动独立保存保持原语义、身份与幂等。两条路径App回归。

## 八项质量的证明方式

美观：保持选定token/布局、浅深和窄屏大字实际截图；可用：录音/文字/查找/编辑追加/删除最短闭环及可解释错误；安全：真实停止确认、源数据/凭证/导出边界与故障原子性；可扩展：当前有界分页/任务容量、代际和旧格式兼容，不增加猜测性扩展点；易维护：共享真正重复的收尾不变量、接口小且责任明确；可审计/可观测：关键操作实际诊断且无内容、故障不妨碍业务；可测试：设备回执接缝+真实SQLite与故障注入；可验收：主机门禁+独立包实际路径与截图，真机空缺不冒称通过。

## Review Focus

1. stop/cancel/close都失败或迟到时，任何dispose/重试/新入口都不得提前释放设备占用。
2. 查询临时删除失败与麦克风未停止是不同状态，不能错误释放设备或永久锁住已释放设备。
3. running状态及错误状态写入失败后，原始错误保留，同一会话仍能再转写。
4. 任务修剪不能使当前永久失败任务自动重跑、删除记录复活或未知sidecar被覆盖。
5. 父删除前没有实际录音片段时不能声称保留，独立保存动作不能进入无法结束的状态。
