# 连续手记 UI 与交互优化：按住录音、明确查找、详情与追加闭环

## Problem Statement

用户实际体验当前念下应用后，发现主题切换不自然、疑似掉帧，录音需要额外点击保存，点击“记一下”时出现的侧边控件不直观。记录、查询、编辑和追加的入口及状态反馈也需要更清楚地区分。

用户已选择第三套“连续手记”设计并批准展开后的录音、查找、详情、追加四条流程。本规格将该方向落实为可实施、可验收的行为；不把静态设计图当成可交互验证，也不把用户感知的卡顿直接归因于动画。

当前仍有具体差距：默认外观为深色；文字输入后会自动查找；查找开始清空旧结果；编辑冲突只有错误提示；追加保存后只刷新首个追加页；普通录音与受控原生录音的部分恢复入口不一致。

## Solution

在已有 Flutter 应用和本地资料能力上实施“连续手记”：

- 首页保留顶部查找、全部／收藏、按创建日期组织的记录，采用左侧时间列和正文主导的连续阅读布局。
- 底部固定“说话／文字”记录区；主要录音方式为“按住说话、松手保存、上滑取消”，另保留点按录音。录音按钮在手指下保持原位，不展开侧边动作列。
- 查询独立于记笔记：文字显式提交，语音松手识别后允许修改，再确认查找；结果追溯原记录或追加记录。
- 详情分清用户正文、原音频、只读原始转写和追加记录；编辑与追加是不同动作。
- 追加始终显示所属原记录，保存成功后回到原记录并定位新内容；失败保留输入。
- 外观选择收进设置；新安装默认跟随系统，已有用户选择保留。主题流畅度以测量而非视觉猜测验收。

图稿中的界面编号代表状态和分支，不是所有用户必须依次走完的步骤。以下文字规则是自包含的实施与验收依据，图稿辅助确定视觉方向。

## User Stories

1. 作为记录者，我希望首页直接展示原文与创建时间，以便快速回看想法。
2. 作为记录者，我希望按日期分组并连续滚动，以便在大量记录中保持阅读位置。
3. 作为记录者，我希望仍能查看全部与收藏，包括收藏的追加记录，以便保留原有找回方式。
4. 作为记录者，我希望按住即可录音、正常松手即可保存，以便减少短语音的操作次数。
5. 作为记录者，我希望实际采集启动后才看到录音状态，以便知道声音是否正在被记录。
6. 作为记录者，我希望上滑看到“松手取消”，移回后继续录音，以便在放弃前可以改变主意。
7. 作为记录者，我希望录音按钮不随反馈面板移动，以便手势稳定、可预期。
8. 作为记录者，我希望松手早于授权或设备启动时不会在稍后偷偷录音，以便控制麦克风使用。
9. 作为记录者，我希望系统中断不会被当成主动取消，以便尽可能保留已采集内容。
10. 作为记录者，我希望保存中、音频已保存与转写中分别显示，以便准确判断资料状态。
11. 作为记录者，我希望保存失败后保留可恢复片段并重试，以便不必重新录制。
12. 作为记录者，我希望重复松手、重试或通知不产生重复记录，以便资料库保持准确。
13. 作为记录者，我希望音频先保存、转写随后完成，以便模型尚未就绪也能记录。
14. 作为记录者，我希望转写失败仍能回放、重试或手动编辑，以便继续使用已有音频。
15. 作为长录音或辅助技术使用者，我希望点按开始、停止并保存，以便不必一直按住屏幕。
16. 作为点按录音使用者，我希望收起后仍能返回同一会话或停止，以便录音状态始终可见。
17. 作为记录者，我希望两分钟上限有提前提示且到时只结束一次，以便避免意外丢失或重复保存。
18. 作为未授权麦克风的用户，我希望仍能写文字并了解如何授权，以便不被完全阻塞。
19. 作为查找者，我希望输入关键词后明确提交，以便控制什么时候开始查找。
20. 作为查找者，我希望用语音说线索、校对识别文字后再查找，以便纠正识别错误。
21. 作为查找者，我希望查询不成为笔记，以便临时线索不会污染记录列表。
22. 作为查找者，我希望文字和语音共用结果逻辑，以便两种入口行为一致。
23. 作为查找者，我希望结果显示原文片段、时间和可用的回放入口，以便核对是否找对。
24. 作为查找者，我希望追加命中可查看本次内容及所属记录，以便恢复上下文。
25. 作为查找者，我希望日期筛选支持全部、今天、最近七天和自定义，以便缩小范围。
26. 作为查找者，我希望无结果时能修改关键词或清除日期限制，以便继续尝试。
27. 作为查找者，我希望失败后保留查询条件，并清楚区分旧结果，以便重试而不被误导。
28. 作为查找者，我希望快速改词或取消后迟到结果不覆盖当前查询，以便看到正确内容。
29. 作为查找者，我希望从详情返回仍保留查询、筛选和滚动位置，以便继续比较。
30. 作为记录阅读者，我希望播放、暂停和拖动原音频进度，以便核对录音内容。
31. 作为记录编辑者，我希望编辑只改变当前正文，以便原音频、原始转写和追加内容保持独立。
32. 作为记录编辑者，我希望未保存离开时确认去留，以便避免丢失修改。
33. 作为记录编辑者，我希望保存失败后输入仍在，以便恢复操作。
34. 作为记录编辑者，我希望版本冲突时保留草稿并能核对新版本，以便不覆盖其他修改。
35. 作为记录阅读者，我希望原始转写只读且容易找到，以便区别识别原文与自己的修改。
36. 作为追加者，我希望先选择文字或语音，并一直看到所属原记录，以便不会追加错位置。
37. 作为追加者，我希望空输入不生成记录，以便资料库不出现空条目。
38. 作为追加者，我希望保存后回到原记录并定位本次追加，以便确认结果。
39. 作为大量追加内容的用户，我希望超过一个分页仍能找到刚保存的追加，以便不用手动翻到最后。
40. 作为追加者，我希望每次追加可独立查看、编辑、回放和删除，以便保留内容来源。
41. 作为追加者，我希望原记录在保存前被删除时保留当前输入，并主动决定是否独立保存，以便不丢内容或复活已删除资料。
42. 作为记录管理者，我希望删除原记录前知道整组范围，以便明确是否包含追加和音频。
43. 作为记录管理者，我希望删除单次追加只影响该次内容，以便原记录仍然保留。
44. 作为记录管理者，我希望确认删除期间新增的内容不被未经确认地带走，以便删除范围准确。
45. 作为日历使用者，我希望核对具体时间并在系统日历确认，以便不把打开编辑器误认为保存。
46. 作为轻整理使用者，我希望只在核对发送文本后使用可选云端服务，以便保留主动授权边界。
47. 作为已有用户，我希望升级后保留我的主题选择与全部资料，以便优化不会改变已有偏好或数据。
48. 作为新用户，我希望默认跟随系统主题，并在设置里切换，以便界面自然一致。
49. 作为大字体或屏幕阅读器使用者，我希望录音、取消、查找和保存都有等价可访问操作，以便不依赖复杂手势。
50. 作为使用者，我希望主题切换、键盘弹出及长列表操作流畅，以便界面反馈自然。
51. 作为隐私敏感用户，我希望诊断不包含笔记、查询、音频或凭证，以便排查问题不扩大资料暴露。
52. 作为试用者，我希望明确区分已验证与仍待真机验收的行为，以便不依赖尚未证明的平台能力。

## Implementation Decisions

### 1. 范围与兼容

- 保留 Flutter 模块化单体、现有记录操作、存储隔离、推理、检索及平台适配边界；不新增生产依赖、数据迁移、状态管理框架或通用服务层。
- 原始 schema 2、备份 v2、旧格式夹具及可重建 sidecar 契约不变。UI 不能为读取或显示方便绕过原有有界摘要、分页和版本检查。
- 不打开受控原生录音或实验加密的默认门禁。普通应用必须实现本轮前台交互；受控原生路径保持同样的保存、取消与所属记录语义。iOS 与目标真机尚未验收的后台能力不得借改版宣称可用。
- 点按录音的后台策略沿用各路径已验证能力；按住手势被系统打断时停止并尽力保留，不能无限等待已不存在的手指。
- 本规格替代上一轮 UI 中“顶部写文字、底部单一记一下”的布局决定，不替代本地优先、平台适配、备份保护等既有 ADR，不改品牌名称。
- 修改现有 UI 断言以表达新授权行为，同时保留数据可靠性、取消确认和平台门禁回归；不能删除有效测试或弱化断言来通过检查。

### 2. 连续手记布局与外观

- 首页顶部为名称与设置、紧凑查找入口；全部／收藏随后；正文区域为日期标题、左侧时间列与原文摘要。语音记录显示可用的播放动作和时长；文字记录不显示虚假音频控件。
- 底部固定说话／文字切换；说话模式主要动作“按住说话”，次级“点按录音”。文字模式明确提交保存，不做失去焦点即保存。固定控件不遮挡列表末项或键盘。
- 不增加底部导航标签、侧边动作列、装饰玻璃、卡片仪表盘、额外文件夹或聊天入口。详情底部区分编辑与追加；删除放入更多。
- 系统中文无衬线；正文约 17、辅助 14、标题 26–28 逻辑像素；至少 44 逻辑像素触控范围，Android 沿用不低于 48 的现有门槛。文字对比度、大字体与屏幕阅读器语义保持项目门禁。
- 基础 token 为白 #FFFFFF、雾灰 #F4F4F4、分隔灰 #E5E5E5、辅助灰 #686868、炭灰 #282828、墨黑 #181818；深色正文 #F2F2F2、辅助 #B8B8B8。红色限录音状态、取消区域与破坏性动作。
- 新安装且没有已存偏好时采用跟随系统；已有偏好优先，移除首页直接切换主题入口。持久化失败不假装成功；快速连续选择以最新有效意图为准，页面状态和已存偏好不能错配。
- 取消明显整页主题过渡，遵循减少动态效果、高对比和减少透明度；缓存与重建优化必须依据实际采样，不能预设动画是掉帧根因。
- 保持主列表原有排序；编辑或追加不将父记录偷偷置顶。日期使用记录保存的创建时 offset；只合并相邻同日记录，跨页相邻同组不重复标题；不能为日期分组重排实际时间顺序。收藏中被收藏的追加记录继续可见。
- 搜索保留现有相关性／稳定排序，不套用首页的日期排序。图稿日期标题仅表示结果来源展示，不能据此改变检索排名。

### 3. 手势与录音会话

- 复用现有采集与保存所有者，在 UI／录音协调边界收口按住手势意图；不由页面直接管理 WAV、SQLite 或启动另一份录音所有者。只有实际需要统一两条已有路径时才增加最小适配接口。
- 逻辑状态包含空闲、准备、录音、取消候选、收尾／保存、已保存、保存失败、已取消；它们不是新增数据库 schema。每次输入意图关联唯一录音会话，只有一项终态决定可被受理。
- 按下进入准备；采集真正启动才显示计时和录音反馈。准备期出现松手、取消或页面不可用，立即使该次意图失效。迟到的授权、文件初始化和麦克风启动必须清理，不能在用户松手后继续采集。
- 首次权限弹窗打断手势后，授权完成需再次主动操作；短触或没有有效 PCM 不产生空记录。不擅自新增最低录音时长门槛。
- 录音按钮位置与命中区域在反馈面板出现时保持固定。上滑仅改变取消候选状态，不暂停、不重启、不创建第二会话；移回恢复松手保存。
- 取消区域采用拇指可达距离与进入／退出滞回，减少抖动；具体距离作为布局参数在原型／设备中调整并记录。状态文案不能仅依赖颜色，触觉反馈不能成为唯一反馈。
- 用户在取消区域松手视为一次明确放弃，不再二次确认；其他放弃录音／失败片段的按钮仍需确认。
- 正常松手结束采集并保存。只有记录资料提交成功才显示“音频已保存”；stop 返回、音频文件存在或 UI 进入保存中均不能充当成功。
- 两分钟截止、正常松手、主动取消和平台结束事件串行仲裁：先被受理的终态决定有效；进入保存后，后来的松手／取消不得删除录音或再建记录。自动截止后即使手指仍按住也显示已结束状态。
- 系统 pointer cancellation、来电、锁屏、切后台不等同明确上滑取消；未启动则废止，已采集则停止并尝试保存／保留。未验证场景不承诺绝对无损或后台持续录音。
- 保存失败保留可恢复内容并可重试，不自动转文字而丢弃音频。只有实际保留成功才说“录音已保留”；保留本身失败必须如实提示。重复通知、重试与转写写回不能重复创建记录。
- 保存成功回列表插入一次，显示可回放音频与待转写状态，不强制跳详情。模型不可用仍可录音保存；转写失败不删除音频。
- 点按录音提供开始、停止并保存、确认放弃，及当前路径支持的收起／返回同一会话；按住录音期间禁用模式切换与收起。任一录音会话存在时，不再启动笔记或查询录音。文字查找不占用麦克风。
- 为屏幕阅读器、开关控制及无法持续按住的用户提供等价点按操作；系统快捷入口的主动启动行为保持可用，进入点按会话，不能要求快捷入口提供不存在的持续触点。

### 4. 查找

- 文字查询从现有自动触发改为显式提交：键盘查找或页面动作提交；没有键盘时页面仍有可达提交动作。编辑关键词立即废止旧请求，清空关键词立即清空结果。
- 语音查找独立标识“按住说出线索／松手识别”，不出现保存笔记动作。结束识别后进入可编辑文字校对，点击查找记录才检索；重说与取消路径明确。
- 语音查询不成为记录；完成、取消、失败及启动恢复时沿用临时查询清理边界。模型未就绪提供文字查找／准备模型；授权与系统中断遵循查询仅前台采集的既有策略。
- 两种输入共用现有关键词／语义检索、降级、有界摘要、分页、代际与取消机制。旧游标失效重新请求正确首屏，持续失效给出可重试错误，不能误报无结果。
- 日期快捷项为全部、今天、最近七天、自定义；最近七天包含今天。设备当前日历日生成范围，各记录按其保存的当地创建日期匹配，起止均包含，不改变既有日期语义。应用／清除筛选后沿用当前已确认关键词执行查找。
- 结果显示来源时间、原文片段、命中追加的标识与所属记录链接。来源摘要必须有界获取；点击播放才按需加载音频，不能为全页结果读取完整正文或预载音频。
- 回放一次只允许一个播放器；开始录音或离开回放上下文先处理已有播放，避免回放声音被录入。
- 命中原记录打开原详情，命中追加打开追加详情，所属链接打开原记录；返回保持关键词、筛选和滚动位置。资料已变则刷新并如实说明。
- 新查找中可保留此前成功结果，但明确显示其所属查询／日期及“尚未更新”，不得冒充新结果。失败保留当前输入与可用旧结果，提供重试。
- 无结果不生成答案；存在日期限制时提供清除筛选，否则建议改词。不能保证换词或清除筛选必然找到。
- 继续使用有界分页。没有精确总数时显示“已显示 N 条”，不能把当前页数量写成全部命中数；只有已知完整结果时使用准确总数。

### 5. 详情、编辑与删除

- 原音频、原始转写、用户正文、轻整理和追加分别表达；只读原始转写不随正文编辑变化。音频提供播放、暂停与进度定位，不新增未经支持的逐字同步。
- 编辑只提交当前记录正文，继续携带期望修订号。保存失败保留草稿，成功才返回；实际文本等于原文时视为未修改，不以“曾输入过”代替脏状态。
- 有修改离开时确认继续编辑／放弃修改。冲突时区分已更新和已删除，草稿保持可见并可由用户主动复制；查看最新内容不先销毁草稿。重新载入并替换草稿须明确确认，不静默覆盖、不自动合并、不新增永久版本历史。
- 迟到转写不得覆盖用户正文；重试转写的结果仍经过存在性与版本检查。记录已删除时不复活。
- 追加记录有自己详情、编辑与回放能力；不提供递归追加入口。所属记录已不存在时给出可解释返回路径。
- 删除藏在更多菜单。删除原记录确认整组数量及音频／追加范围；删除单次追加明确原记录保留。提交删除时再次验证已确认的范围，范围或成员变化则重新确认；必须在存储操作边界保证，不能只做提交前的一次有竞态 UI 检查。
- 删除成功后才离开；失败保留页面并可重试。既有系统日历事件不因删除笔记而删除。
- 保留轻整理单条确认、默认关闭、凭证保护及独立结果；保留日历核对具体时间与真实回执语义，不能把打开系统编辑器显示成已保存。

### 6. 追加

- 从原记录选择追加文字／语音，始终显示所属原记录；打开入口不创建空记录，空白文字不能保存。
- 文字编辑框只含本次输入；语音采用同样的按住／取消规则，文案为按住追加／松手保存追加。失败保留当前文本或可恢复音频。
- 保存操作以实际返回的新追加身份驱动返回与定位；重复点击、网络无关的本地超时重试和迟到回调不能重复提交同一次保存意图。已有稳定会话 ID 优先复用；文字路径采用最小提交意图约束，不改原始 schema。
- 成功后回原记录并定位新追加，可短暂中性高亮；减少动态效果时直接定位。不能为定位加载全部追加：以返回 ID 获取有界窗口或等价有界定位方式，并保留其余内容的分页访问。
- 延续追加的稳定时间顺序；超过40次追加时也必须看到本次新增，不只刷新首个分页。用户可继续向前／向后查看已有内容。
- 保存时原记录消失：文字与两条录音路径都保留当前输入并解释原因；仅在用户选择保存为独立记录后才转换，不复活原记录、不静默降级。独立保存也防重复。
- 用户放弃追加不改变原记录；单次追加删除不删除原记录。语音追加先成功保存音频，再异步转写。

## Testing Decisions

### 测试边界与既有先例

优先一个最高层边界：NianxiaApp 的公开用户操作，注入真实临时 Notebook 和可控 MicrophoneInput／原生端口／推理运行时。通过按下、移动、松开、输入、返回等操作，验证用户可见状态和实际保存的记录、音频、关系与数量，而非私有字段、组件层级或状态命名。

沿用已有整应用 UI、approved UI flows、录音 UI、异步分页、恢复、主题偏好与原生交接回归。控制器测试仅补授权迟到、启动迟到、终态仲裁、保存故障等难以稳定从 UI 定位的不变量；SQLite／记录操作已有 CAS、迟到转写和删除不复活测试继续保留。测试接缝基于现有注入能力，不为这次 UI 创建一套平行业务 mock 架构。

### 必须覆盖的行为

1. 正常按住保存、滑入取消区、移回继续、区域抖动、取消松手与系统取消不同语义；按钮位置不变。
2. 权限未决、WAV 初始化及设备启动未完成时松手／取消；迟到成功不得继续录音；授权后需重新操作。
3. 两分钟到时与松手／取消交错、重复通知和重试；结果只能是一个终态且最多一条记录；空 PCM 不生成记录。
4. 普通兼容与受控原生两条路径分别验证保存失败、保留失败、重试、主动放弃确认、转写失败和会话互斥。
5. 点按收起／返回保持会话；快捷入口无持续触点也可操作；未通过门禁的能力不因 UI 改版启用。
6. 新安装默认系统、已有主题偏好保留、偏好写入失败与快速选择、系统主题变化、减少动态效果和高对比。
7. 首页超过95条分页、相邻跨页同日、跨 offset 日期、收藏追加、刷新及返回保持位置；不引入全量读取。
8. 文字显式提交、语音校对确认、模型未就绪、取消与清理、快速改词、过期结果标识、日期快捷范围和边界、失效游标。
9. 搜索相关性顺序不变，分页数量不冒充总数；追加来源链接和按需回放；详情返回位置保持。
10. 编辑保存／失败／无实际修改返回、用户草稿与新版本冲突、已删除、迟到转写不覆盖。
11. 文字与语音追加的成功／取消／失败、重复提交、原记录并发删除与用户确认独立保存、超过40次追加的有界定位。
12. 删除原记录与单次追加范围不同，确认期间组内新增／移除使旧确认失效，音频清理和检索删除继续正确。
13. 320逻辑像素窄屏、双倍字体、中文键盘、深浅主题、辅助技术等价操作；焦点、返回、提示与主要按钮可达。
14. 既有本地优先、数据版本、恢复、日历确认与单条云整理隐私回归不得退化。

### 实际平台与性能验收

- 修改影响范围的测试先通过，再执行项目主机门禁 bash tool/check.sh（工具测试、静态分析、Flutter 测试）。原生代码改动时追加对应原生测试与构建；不因仅修改图稿重新运行产品全套测试。
- 独立测试包／受保护 runner 执行真实录音、键盘与页面闭环。先验证身份及专用目录，只使用合成资料和公开夹具，不覆盖安装、清理或读取正式应用资料。
- 主题切换先建立可复现基线：同一设备、刷新率、构建模式、记录负载和模型状态，切换至少30次并区分首轮／稳定轮次；采集输入至主题呈现延迟、build／raster 帧时间及超出设备刷新预算的比例。固定实际条件后对比修改前后，不用 debug 或图片观感证明流畅。
- 日期分组、追加定位、搜索父摘要和回放入口测有界读取与分页开销；不得退化既有检索与存储不变量。必要时沿用现有一万条性能夹具，不能把重复向量当语义质量验收。
- 视觉验收对照已选连续手记与四流程图，分别检查浅／深、正常／失败、大字体／键盘；截图只证明画面，不能替代手势与保存行为。
- Magic8、iPhone17的自然手势、TalkBack／VoiceOver、系统中断与主题手感分别实测。设备或完整Xcode不可用时明确保留未验收项，不以Android模拟器或构建成功替代双平台验收。
- 诊断仅用现有封闭枚举、数值及随机身份；不记录正文、查询、文件内容或凭证。未复现的卡顿保留证据缺口，不杜撰根因。
