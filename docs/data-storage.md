# 数据存储、升级与备份契约

适用：schema 2、备份格式 2；2026-11-14补充独立sidecar、原生恢复与门控age备份。这是本地优先单用户应用的数据保障边界，不是服务端高并发或跨设备同步方案。存储实现不要求 UI、语音引擎或向量模型参与升级。

## 当前新增边界

- `jobs.sqlite` v1与`jobs-owner.sqlite`是可选任务缓存；仅保存source ID/revision、模型代际、状态、次数和随机租约，源资料提交后再确认。竞争/坏缓存安全暂停，源库仍可用，未来版本原样保留。
- `diagnostics.sqlite`独立有界：5MiB/7天/256待写；封闭字段不含用户内容、路径、查询、密钥或密码，诊断不进入完整备份。导出前预览包含项。
- 新搜索摘要每页≤40，标题≤120/片段≤150 Unicode scalar；只把排名元数据写入受限私有scratch，不把整库正文传给UI。scratch预算256MiB/2MiB页缓存/两个上下文/五分钟空闲；可重建且不进入备份。
- 原生录音草稿和原始`audio/`分开；source commit后才提示保存。native失败/未知恢复标记保留，恢复列表只接收受管ID。丢弃已认领片段先写持久Dart标记，再由native独立确认；不能删除已成为原记录的音频或让丢弃片段重生。
- 标准age密码备份包装现有流式完整v2快照；认证到EOF和预检完成后才合并，旧ZIP导入仍支持。取消不是立即中止不可抢占KDF，UI等待清理完成。密码自行保管，无恢复后门；原型有资源/互操作/Android完整链路证据，但Gate-B未过，普通应用未默认启用。
- 未加密的可读文本/音频导出与完整备份分开，前者不用于完整恢复。明文临时副本放私有目录并尽力清理；分享返回不证明外部保存。自动系统备份排除、设备私有存储和应用层加密是不同边界。

最新实测与未通过的平台门禁见 [验收报告](validation/2026-11-13-architecture-ui/final-report.md)。

## 数据所有权

| 数据 | 持久位置 | 升级/恢复原则 |
| --- | --- | --- |
| 当前正文、原始转写、录音引用、时间/时区、修订、收藏、追加关系 | `records.sqlite` 的 `records` | 用户原始资料，不能依赖缓存恢复 |
| 原始 WAV | 私有 `audio/` | 不因数据库迁移移动、重编码或改写 |
| 云端整理 | `record_organizations` | 按源修订、格式版本和模型代际解释；损坏可失效 |
| 语义向量 | `record_embeddings` | 有界 Float32 小端 BLOB，维度/格式/模型/源修订必须匹配；可重建 |
| 字符倒排、HNSW 图与待建图队列 | 私有 `search-index.sqlite`（含 WAL/SHM） | 仅派生访问路径，可重建；不进入备份，不改原库 schema |
| 恢复去重映射、偏好与模型代际 | `restored`、`metadata` | 数据库迁移保留；备份不导出设备设置与缓存 |
| 已授权删除/未提交导入副本的清理意图 | `pending_media_deletions` | 先持久化再操作文件；重启重放，仍有记录引用的文件不删除 |
| 来源不明的未引用音频 | 私有 `quarantine/<随机ID>/` | 保留原始字节，不在启动时永久删除；目前没有隔离区管理 UI |

`Storage` 的持久 isolate 独占正式 SQLite 连接；内部 `RecordRepository` 执行数据库读写和 CAS（记录 ID + 源修订 + 模型代际）校验。`Notebook` 拥有录音落盘、媒体生命周期和业务操作；`NotebookSession.close()` 统一等待数据库、模型调度和后台任务的关闭。界面不执行 SQL 或迁移。`backup_codec` 使用独立原始 DTO，不能通过完整 `Record.toJson()` 导出缓存。

原文编辑使旧向量不可用，但不依赖第二次缓存写入才能成功；合法的旧整理可展示为过期。非法 JSON、字段类型不匹配、未知格式、非法向量仅使对应缓存失效，不能隐藏原始记录或阻断详情/关键词/备份。普通列表不读取向量载荷，检索命中结果不保留向量。常规检索使用下述本地访问路径；索引 I/O 失败时明确提示并从原始资料降级查找，不能将缓存失败误报成原始记录保存失败。

## ANN候选的批量回读（2026-11-13）

- 原`get`与其他读取路径保持不变；`getBatch`最多64条完整记录，复用同一`_query/_record`，每批只读取一次模型元数据。遗漏ID跳过，返回列表不约定SQL顺序。
- ANN重排每批实际16条，批查`vector_key→id`和原记录，按原始ANN候选顺序评分；完整organization/transcript/favorite/vectorRevision等字段保留，搜索结果仍剥离向量。未新增异步窗口，原编辑/删除/模型/外部写入检查仍在查询尾执行。重复缓存key视为坏缓存，走原文扫描和重建。
- 位模式字节级测试及旧算法差分已在主机和Android ARM64 AOT验证；完整源库与图/分数位串一致。批次限制不等于总结果内存上限，大organization/长正文仍需单独测量。实际p95和RSS取舍见 [对照报告](performance/search-tail-100k-2026-11-13/README.md)。

## 向量分配与页缓存预算（2026-11-13）

- Float32 解码使用独立数值缓冲区，不保留调用方 BLOB 别名；归一化复用一份 Float64 缓冲区，保留 double 精度、有限/非零/维度检查和稳定缩放/求和顺序。返回值仍为 List<double>，固定长度；现有消费者只读、编码或复制，不依赖 growable 行为。
- 源库与检索 sidecar 连接分别设置 `PRAGMA cache_size=-2048`，按当前页大小请求约 2MiB 页缓存；这是连接内建议预算，不是整个连接、VM 或 App 的 RSS 上限，也不修改数据库 header 的持久默认缓存值。真实目标设备仍需验证 I/O 取舍。
- 索引内容指纹的 SHA 输入改为 Uint8 缓冲区，拼接字节/顺序完全相同，不触发既有缓存迁移或重建。原库 schema2、备份v2、sidecar3及模型/图参数不变；十万条源库和完整图内容验证一致。
- 性能、数据指纹、失败记录和平台验证见 [内存与首查报告](performance/search-memory-100k-2026-11-13/README.md)。

## 首次查找与后台建图（2026-11-13）

- 冷启动、完整源对账未完成或缓存不可用时，查询直接按 64 条 keyset 页读取原库，不等待文本倒排或整张 HNSW 图。准备中的语义候选全部参与精确余弦计算，仅保留前 128 条（有日期条件时 1024 条）；精确关键词结果保持完整。已就绪的查询合并 ANN 和尚未建图的精确候选，避免将未完成图当作完整语义覆盖。
- `pendingSemanticRecords` 描述本次即时检索涉及的待就绪向量，不是持久任务进度；缓存重开待校验时，已有图的向量也可能计入。提示明确说明本次直接读取原记录，后续查询会在索引就绪后加速。
- 后台维护由 `SearchIndex` 拥有和收尾。文本准备分 64 条、图写入分 8 条事务执行；查询活跃时让路，压缩清图前同样检查活跃查询。查询检测到缓存未就绪或源代际改变时走源库路径，不等待自身结束。关闭等待已经接受的查询和异常降级读取，再中止后台续建并释放连接，不等待整库建完。
- 源库分页校验原始内容代际、模型和外部 `data_version`；同连接、同模型的派生向量持续写入不会让查询每页重启。已经扫描过的页面随后新生成的向量可能到下次查询才参与排名；原文编辑、删除和模型变化仍受校验，不能返回已删除记录或覆盖编辑。
- `CompactGraphStore` 在原有 HnswStore seam 后封装紧凑 SQLite 存储：节点使用整数主键，邻接层/节点编号使用有界 varint BLOB，原精度 Float32 向量按维度计算槽数、以约 4KiB 载荷分块单独存放（512D 每块 2 条）。向量块使用普通 rowid 表及复合唯一键，避免大 BLOB 作为 WITHOUT ROWID 索引载荷；邻接和删除标记更新不写向量块；查询只取对应向量切片，使用预编译 SQL 和 Float32 view 减少分配。槽位从已提交节点的唯一索引推导，避免独立游标丢失或回退覆盖缓存向量；事务失败后丢弃工作集，重开读取已提交内容。图算法、M=12、construction ef=80、查询 ef=200/upper beam=8 均不变。
- 倒排词条使用整数词典 ID，关联使用原记录整数 rowid；计数变化在每批事务内汇总，词典 ID 缓存有界。rowid 复用时先清旧记录的派生引用。
- sidecar 独立升级为**缓存格式 3**，使用 application ID 标识；先验证原库别名、缓存版本及表集合，识别到已知缓存 v1/v2 时关闭并物理替换缓存文件，释放旧页而非只 DROP 表。原库 schema 2、备份 v2、原始文本和 WAV 均不迁移。未来或未知缓存版本保留并降级；拒绝缓存路径的符号链接及指向原库/其 WAL/SHM 的别名。已知旧缓存物理重建会释放旧页；原地删除/压缩图仍可能保留空闲页，规模报告按全新 sidecar 测量。
- 后台失败不影响已保存资料；错误由维护 Future 记录，已知损坏至多自动重建重试一次，查询仍可从原库读取。`waitForSearchIndex` 是显式准备/验证工具的等待接口，交互查询不调用它。

## 离线检索访问路径（2026-11-13）

- `SearchIndex` 与原库一起由 storage isolate 持有。`RecordSearch` 负责查询向量推理，关键词匹配、索引维护与排名都在 worker 中；不增加服务、生产依赖或网络请求。
- 关键词保留全半角/大小写归一化后的精确子串契约。对 Unicode 字符建立 1/2/3-gram B-tree 倒排；选择最稀少的 gram 并最多交叉检查 8 项，再用完整归一化正文 `contains` 和最新原记录验证。中文单字、双字、长词、标点和空格不依赖分词，也不要求系统 SQLite 支持 FTS5。
- 日期以创建时间加记录保存的 offset 得到本地日期。日期范围与 gram posting 通过有界计数探测选择较小访问路径；日期优先按 `(day,id)` keyset 翻页，后续页只保留 tuple 下界和日期上界，避免同日反复扫描。语义日期候选使用 `(dimension,day,vector_key)` 索引；范围内至多 1024 条时精确比较，范围较大时扩展 ANN 候选预算。
- 语义检索使用磁盘 HNSW，M=12、构建 ef=80，查询上层 beam=8、底层 ef=200、至多 128 个候选；宽日期范围最多 1024 个候选、ef=1400。上层多路入口避免高维密集簇中的单路贪心局部极小；构图和原向量不变。随后重新检查存在性、源修订、模型代际和维度，按原始向量做精确余弦重排，保留原有 0.60 合成烟雾测试阈值。ef 是候选宽度，不是距离计算次数上限；余弦值不代表置信度。界面明确标记近似语义匹配；它可能遗漏相关记录，完整精确关键词命中不截断。
- 文本索引准备与语义图构建分开。源数据按 64 条对账，待建向量以 durable queue 保存在 sidecar，每 8 条图事务后让出 worker。关键词不必等待初次语义图建完；已准备文本可在图维护期间响应并发关键词查询。退出后保留已提交批次，下次语义查询继续处理队列。
- 启动后的第一次检索、外部连接写入或超过 4096 个脏 rowid 时会分页对账源库；正常查询不再每次读取/归一化全库文本或解码全部向量。SQLite 同步 update hook 仅登记 rowid，不能在 hook 内重入 SQL；回滚后重新读取最终源值，处理级联删除和 rowid 复用。全文本对账完成前禁止旁路读取未完成索引；原记录/模型发生变化时重试当前查询。
- 原始提交独立于 sidecar 事务。缓存维护失败保留原始资料并在下次重试对账；已知损坏文件隔离后重建，旧版 JSON/新版二进制邻接、向量和 entry 指针损坏可从原向量恢复。未来 sidecar 版本只降级读取原资料，不覆盖未知缓存版本。图删除保留路由墓碑，超过 1024 个墓碑重建派生图；同一向量的不同生命周期使用不同 key，不复用墓碑。
- 图节点采用有界 LRU：最多 4 个维度工作集，每组最多 2048 个节点，并按维度将向量载荷预算限制在约 4 MiB（另有邻接、对象及 SQL/VM 内存）；不把全库向量常驻内存。HNSW 仍是近似算法，访问量和额外空间取决于数据分布。冷建与源对账有线性成本；常见关键词大量命中时，返回/排序/跨 isolate 传输依然与命中数相关，当前没有搜索结果分页或无限规模承诺。

算法依据：[HNSW 原论文](https://arxiv.org/abs/1603.09320)。选择可移植字符倒排是为了保留短中文子串语义；[SQLite FTS5 文档](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)中的 trigram 查询不能单独覆盖不足三个字符的匹配。

## 执行、异步读取与关闭

- 打开库、迁移、完整性检查、快照、列表/详情、任务查询、检索扫描/排序及恢复合并均在专用 storage isolate 执行。UI 只发送数据请求，不接收 SQLite handle、原生指针或事务闭包；异常按类别转为可处理的失败，不传出包含笔记参数的 SQL 错误。
- `Notebook.get`、`detail`、`page`、`children`、`prepareOrganization` 与模型版本变更都是异步 interface。`themeMode` 是启动时预载的偏好缓存，保存主题须等待持久化成功。显式全量 `records` 读取仍可供验证/工具使用，首页和后台调度不调用它。
- 首页一次请求 40 条摘要，正文只取前 600 个 SQLite 字符，不读转写、整理、向量载荷。追加数量由索引查询直接返回，行构建不再另查整库。按创建时间降序、ID 升序做 keyset 分页，时间相同时仍不重不漏。
- 详情按需读取完整原文，并按父 ID 索引分页读取追加摘要、返回准确总数。显示摘要不替代原始资料；编辑、转写、备份使用完整记录。后台按 ID 每批查询最多 32 个待处理项，不复制全库。
- 游标携带内容代际；发生正文/收藏/关系变更后，下页返回重置标记。界面用请求序号丢弃过期回包，内容刷新重建已加载窗口并保留滚动位置；只有切换筛选重置窗口。向量/整理/模型状态通知与首页内容通知分开。
- 数据库语句在同一 worker 顺序执行。恢复准备和检索扫描可在安全的 await 处让出，普通编辑可继续；最终合并事务内不让出该连接，期间新请求等待，UI 事件循环持续响应。
- `Notebook.close()` 和 `Storage.close()` 可等待且幂等：拒绝新操作，等待已接收的多步骤操作、媒体租约及存储请求释放资源。widget 的同步 `dispose()` 触发同一路径；测试和显式关闭流程必须 await `close()` 后再删除临时目录或重开库。在途推理的迟到结果不写回，关闭期间也不新发起云端请求。
- 删除在首次异步数据库请求前登记完整“删除＋清理”屏障；新媒体租约等待该屏障，避免把导入准备中的媒体当作旧清理意图删除。多个删除和失败路径均释放屏障。worker 意外退出会令等待请求明确失败，不清空或重建资料库。

## schema 升级

- 新库直接创建 schema 2。现有库先检查 `PRAGMA user_version`；未来版本、非空未知 version 0、含未知表/列的 v1 均拒绝打开，不重置库。
- 通常通过只读连接识别。部分系统 SQLite 无法用只读连接建立 WAL 辅助文件（`SQLITE_CANTOPEN`），仅在该错误时以 read-write 方式允许 SQLite 自身恢复/建立辅助文件，然后再次识别；识别前不执行应用 DML、迁移或切换日志模式。
- v1→v2 先 `VACUUM INTO` 生成一致数据库快照，使用临时文件再原子替换。每次重试刷新快照，避免旧版本在失败后新增的编辑被旧快照覆盖。
- `BEGIN IMMEDIATE` 内复制原始列与恢复映射，双向 `EXCEPT` 验证原值，迁移可识别缓存，替换表并推进版本；提交前执行 `foreign_key_check` 与 `quick_check`。失败回滚并关闭连接；原始 WAV 不参与重建。
- 迁移事务成功并通过首次校验后清理快照；清理失败不会把已提交的升级误报为失败。正常运行使用 WAL / `synchronous=FULL`。

快照只保护这次迁移及首次校验窗口；不是任意时刻回退旧 APK 的机制。开放新版本写入后，旧 APK 应拒绝新 schema。不能仅替换数据库主文件而忽略 WAL，也不能把临时迁移快照当作音频完整备份。严重 I/O/设备损坏仍需用户另存的完整备份。

下次 schema 变更必须增加独立、有明确起止版本的迁移步骤，保留已发布旧版的冻结夹具；不得修改旧夹具使测试迎合新实现。覆盖原始值/关系/恢复映射、失败重试、未知版本、DELETE/WAL 中断恢复，并在目标平台 SQLite 上运行。新缓存编码应使用新格式/模型代际，避免把缓存升级混入原始数据转换。

## 完整备份格式 2

用户仍选择一个未加密 ZIP 文件。采用 STORE ZIP64，布局为：

```text
manifest.json             # format=nianxia, version=2, minimumReader=2
chunks/00000000.json       # 原始记录 DTO + 对应 WAV 名称、字节数、SHA-256
text/00000000.txt          # 可读文本分块
…
audio/<UUID>.wav
```

- 每个 JSON 块最多 256 条且不超过 4 MiB，可读文本块也不超过 4 MiB。清单不超过 16 MiB，ZIP 条目不超过 1,000,000。原始正文/转写各不超过 100,000 字符，WAV 单项最多 3,844,096 字节、时长不超过两分钟，与当前采集契约一致。
- 移除 v1 的整包 512 MiB / 10,000 条限制。空间和元数据仍有界，并非无限容量。已实际回归超过 512 MiB 的完整音频包及超过 10,000 条记录；超过 4 GiB 的实包尚未验证，ZIP64 格式支持不能代替设备实测。
- 导出从 SQLite 一致快照分页读取。哈希、文件编码/解码在 isolate 执行；大库合并使用暂存 SQLite。源快照和最终合并事务在持库 worker 执行，不阻塞 UI；最终事务仍会占用该连接，普通数据库操作在此期间等待。文件名/引用集合与有界 manifest 仍会占用随条目数增长的内存。
- 媒体租约覆盖导出/恢复：暂时拒绝删除，允许正常新增和编辑。导出得到操作开始时的一致快照，之后的修改不混入该包。恢复前预检设备可用空间，I/O 失败时回滚而不是重置原库。
- 检查条目白名单、重复、链接、压缩类型、声明大小、CRC、SHA-256、WAV 格式/时长及追加关系。逐条读取 ZIP header，先读 manifest 和记录块，核对媒体引用后再写音频，不构造全量 Archive；本地 header 也须为 STORE，逐条显式开启 CRC 与严格错误处理。只接受 STORE，不接受压缩炸弹。未知格式或校验失败不开始合并。
- 全部校验及媒体准备后，由 UI 处理进度/取消，再向持库 worker 发出最终提交许可；事务开始前、每 64 条及 COMMIT 前检查取消标记，取消使整个事务回滚。COMMIT 后的迟到取消不能把成功误报为回滚。停止写取消标记后才清理工作目录。原库在一个事务内合并。完全相同的内容跳过，冲突保留现有行并新增副本，父子引用重映射。音频在复制前记录持久清理意图；未提交副本可重启清理，已提交的引用不会被误删。
- 本地音频缺失不阻止有效备份恢复：保留旧行，导入完整音频副本；再次导入可去重。恢复的 `running` 转写改为 `pending`，不重放付费整理。
- 兼容冻结 v1 读取及旧去重指纹；v1 自身仍受其 512 MiB / 10,000 条 / 16 MiB 元数据限制。新版只导出 v2，旧 App 无法读取 v2。

备份包含当前保存的正文、原始转写、原始音频、收藏和记录关系；不包含模型、Key、向量、整理缓存、设备偏好或尚未保存的草稿。它不是永久编辑历史，已被用户替换的旧正文版本不在本阶段新增保存。导出由用户自行另存，分享返回不能证明外部副本已保存。

## 验证边界

主机测试使用真实持久 storage isolate、临时 SQLite、有效 WAV 和 ZIP，不使用正式笔记库。widget 测试在真实异步事件循环等待 isolate 回包，保留正常动画时钟，不用同步假存储掩盖问题。迁移测试对两种日志模式、六个阶段使用独立进程和 OS 强制终止；恢复测试覆盖重复、冲突、取消、空间不足、SQL 失败与坏缓存。Android 存储/模型集成通过独立 `app.nianxia.nianxia.test` 包及受保护 runner 执行，正式包不卸载、不清数据。

iOS 桥接的空间 API 已实现；完整 Xcode 构建、iPhone 真机文件系统/中断恢复尚待验证。WAL 与事务不能防止设备丢失、文件系统损坏或用户删除所有副本；本地SQLite/WAV和普通明文导出未增加应用层加密；单独的age密码完整备份原型仍受Gate-B控制。本阶段不实现跨设备同步、云端备份、高可用服务集群或永久版本历史。
