# MVP 实施与验收

基线：[规格 #1](https://github.com/destinyTaoTao/nianxia/issues/1) 与子任务 #2–#15，沿用已确认设计，不增加需求访谈。本轮直接在当前 `main` 实现并提交，不推送。已有 AGENTS、领域词汇、ADR 和设计资料保持不变。

## 实施顺序

1. #2：Flutter 双端脚手架、SQLite 持久化、应用操作入口、文字记录与主题。以真实临时数据库验证创建、重启、编辑、删除及保存失败。
2. #3：WAV 采集/回放、两分钟上限、恢复标记与启动恢复。验证有效文件先落盘、取消、损坏、父记录删除及中断。
3. #4：统一查找入口、中文/技术词归一化与显式日期过滤。验证编辑、删除、追加和无结果，测 1,000 条基线。
4. #5：原生日历编辑器与字段校验，保持 saved/cancelled/unknown/unavailable。验证日期、重复操作与复制后备路径；真机提醒独立验收。
5. #6：固定模型清单、流式下载、SHA-256、原子启用与持久任务；SenseVoice 工作 isolate。验证下载失败、旧修订、静音和删除写回。
6. #7：BGE WordPiece/CLS/归一化与共享 ORT CPU 路径，统一检索和串行推理。验证真实模型及关键词降级；质量与性能不预宣称达标。
7. #8：临时语音查询，经同一转写/查找操作，完成、取消、失败及启动清理。
8. #9：系统快捷动作与原创图标，保护当前录音会话。检查自适应、单色与小尺寸。
9. #10：收藏、独立追加与整组删除，复用保存/查找/任务边界。
10. #11：DeepSeek BYOK、安全存储、逐次文本确认、严格结果校验及修订绑定。不执行真实付费调用。
11. #12：事项候选进入既有日历核对，无自然语言时间解析或自动写入。
12. #13：版本化导出，白名单包含用户数据与音频，排除凭证和模型，流式处理。
13. #14：暂存校验、冲突副本、关系重映射、重复幂等恢复及索引重建。覆盖恶意路径、损坏与中断。
14. #15：分析器、完整测试、可行构建、运行截图与双轴独立评审。记录签名、设备和环境限制，不关闭未验收 Issue。

## 测试边界与完成标准

使用规格已经约定的最高可行边界：应用公开操作 → 可观察状态与真实 SQLite/私有文件持久结果。外部硬件、系统编辑器、下载服务器和付费 API 可注入受控适配器；不通过替身宣称平台能力已验证。逐个行为先观察失败再实现，单文件经常运行，最终运行完整测试与 `flutter analyze`。

重点防回归：保存失败不得成功；编辑/删除期间旧任务写回；取消/重试/中断恢复；查询和密钥不进备份；导入冲突不覆盖；日历未知不当成功；模型不可用保留关键词路径。

## 视觉 token 与 brief 审查

使用 frontend-design。浅色：背景 #FFFFFF、表面 #F7F7F8、正文/主按钮 #171717、辅助 #666666、边界 #E5E5E5、反色 #FFFFFF。深色：背景 #212121、表面 #303030、正文/主按钮 #F5F5F5、辅助 #B4B4B4、边界 #4A4A4A、反色 #171717。

系统中文无衬线；标题 28/24、正文 17/16、辅助 14；左对齐时间线，最大阅读宽度 720，24 外边距；48 最小触控区。首页底部双入口，文字输入始终可见；详情按正文、追加、原始转写、派生结果排列。原创标识用便笺折角与三道声纹，其他界面安静留白，不使用聊天气泡、渐变、装饰波形或重复卡片。用户触发的面板过渡约 180ms，尊重系统减少动态效果。

审查：黑白灰符合已确认 brief；唯一视觉记忆点是声纹便笺标识，时间线以内容为主，主动作有明确中文标签，浅深主题共用语义层级。实现后用运行时 widget 截图检查布局，真机检查另行记录。

## 环境与实现取舍

- 起始为空提交仓库，无产品代码、测试、Flutter、JDK、Android SDK 或完整 Xcode。工具安装放在用户本地独立目录，不修改 shell 配置。
- 存储采用直接 SQLite SQL 与版本迁移，减少首版生成器工具链；遵循相同持久化与事务边界。Drift 在规格中为“优先验证”，不是硬性依赖。
- 模型与第三方运行时在实现时核对官方资料并固定。新增依赖服务于已授权 MVP，不引入账号或遥测。

## 胶囊呼出补齐

用户原始目标包含无需先进入首页的胶囊记录，现有桌面动作不足以覆盖。继续在同一应用操作/真实文件与 UI 测试边界实现：

1. Android 使用单一 translucent FlutterActivity / 单一 Notebook，通过快捷设置磁贴、白名单 `nianxia://capture` 或 `app.nianxia.CAPTURE` 直接显示胶囊；不添加悬浮窗、无障碍服务、常驻监听或后台麦克风权限。
2. iOS App Intents 提供“记一下/找一下”，并接受相同只含操作的 URL。系统将应用带到前台的胶囊界面；不宣称具有跨应用悬浮或绕过解锁能力。缺少完整 Xcode 的验证限制仍存在。
3. 复用 CaptureController 的两分钟上限、PCM 保存、恢复与版本边界。重复呼出不重启录音；返回键停止保存；保存完成/失败/丢弃状态明确，退出前不隐式删除有效录音。
4. 沿用既有黑白灰 token、系统字体和原创标识。顶部左对齐标识+状态+真实时间，下方真实音量和“停止并保存”，圆角 32 的紧凑单面板（最大宽 400），空白处不显示记录库。48dp 操作、字体放大可换行，无装饰动效。
5. 验收：应用 UI 回归、分析器、全套主机测试、Android 构建与模拟器冷/热启动、重复呼出、保存/返回/权限失败，并保留实际截图。物理 AI 键映射及 iOS 安装仍需目标系统验证。

## 当前模拟器阶段

2026-11-09 用户明确将真机验收后移，先使用模拟器继续开发与回归。保留双端产品目标，真机条件不再阻塞 Android 模拟器阶段；iOS Simulator 仍需完整且兼容本机 macOS 的 Xcode。

- Android API 36 ARM64：补测系统日历接入、息屏保存和强杀恢复。开发模拟器使用 Etar 离线日历接收合成事项，不向念下安装包增加依赖或日历权限。
- Android 不具备通用的提醒分钟预填契约，将字段明确为“计划提醒时间”，在系统编辑页前展示所选计划和手动设置要求。沿用灰度 token、原有字体、单列可滚动表单，不新增页面或装饰。
- 短暂息屏可能先唤醒而未到 `paused`，单次查询也有时序竞态。改用受保护的系统息屏广播通知当前采集器，走既有保存路径；启动前检查亮屏及解锁状态，异常或超时不启动采集。普通 `inactive` 继续保护重复快捷动作。
- 测试仍在应用公开操作、真实持久结果和外部系统适配边界进行。模拟器通知、虚拟电话、性能基线与真机结果分别记录，不将未观察到的行为标为通过。

### 常用流程延续打磨

验收关注清空和日期恢复能找回实际本地记录、小屏大字体键盘下无布局异常、已有保存及提醒说明回归、深浅截图与模拟器导航；iOS 和真机仍沿原安排后移。

## 录音面板权限降级

按 #3“拒绝权限可转文字”补齐应用内录音面板：录音未开始且没有音频草稿时，直接进入文字编辑；从已有记录追加语音发起时保留 parentId，转为文字追加。只有明确失败且无草稿才提供这个入口，有音频草稿的失败仍保留重试保存/丢弃路径，语音查询也不会变成新笔记。不改采集器、检索或平台权限语义。

测试经过公开 openRecorder 操作，使用现有麦克风适配器边界模拟权限拒绝/停止失败，最终检查真实 SQLite 记录、父子关系和音频文件；原生权限界面单独检查。整体 iOS/真机、标注语料、真实 USB 麦克风和手机性能验收仍未因此完成。

四项新回归及全量 52 项主机测试、静态检查和 ARM64 Release 构建通过。原生 Android 实际拒绝权限后检查新建/追加的文字入口和编辑器跳转，并恢复原权限与浅色首页；既有数据未编辑。Standards / Spec 独立静态评审均无确认的增量问题。
