# nianxia 第一版 MVP 设计

状态：已发布为 [GitHub Issue #1](https://github.com/destinyTaoTao/nianxia/issues/1)，标记 ready-for-agent，以该规格为实施基线。技术候选仍需验证，正式名称和图标定稿不阻塞技术验证。

## 当前实施补充（2026-11-14）

本文件保留原MVP范围；本轮架构与UI决策以 [批准规格](superpowers/specs/2026-11-13-architecture-and-interaction-design.md) 为补充，最新实际结果见 [验收报告](validation/2026-11-13-architecture-ui/final-report.md)。核心使用深浅中性主题、顶部查找/写文字、底部单一录音；Android Material3，iOS无原生玻璃验收证据时使用实色，并遵循减少动态/透明度与高对比偏好。

原始资料schema2与备份v2保持；摘要分页、独立任务缓存、脱敏诊断及恢复管理已实现。原生后台录音与age密码备份处于受控门禁：Android独立包有实测证据，完整iOS/Xcode及两台真机尚未接入，因此普通应用没有默认启用它们。早期候选技术的历史文字不作为本轮已达标承诺；真实手机质量、P95、热量/电池、系统日历保存/提醒仍需实机验收。

## 1. 目标与已确认边界

帮助用户快速记下产品、技术与日常想法，用自己的话找回来，并把明确安排加入系统日历。

- 国内中文场景，Android 与 iOS 两端。
- 模型就绪后离线录音、转写、文字与语音查找，首版不内置生成式大模型。
- 云端仅可选精整理，默认关闭，用户主动选择文本；自带 API Key，不建设产品代理服务。
- 模型首次下载，下载前可用文字与录音基础能力。
- 先自用和小范围试用；验收设备为荣耀 Magic8、iPhone 17 标准版，系统版本验证时记录。
- 快捷入口、日历提醒、简洁直白 UI 与适度动效。

以下交互、开发顺序和指标作为实施基线；技术候选须经阶段 0 验证。小而美指交互与职责收敛，不代表离线模型体积很小。

## 2. 最小功能范围

| 必须完成 | 第一版边界 |
| --- | --- |
| 语音与文字记录 | 优化 5 秒到 2 分钟；建议两分钟自动停止保存，提前显示剩余时间；不做长会议 |
| 离线转写、编辑、回放 | 说完后转写，保留音频和原始转写；不做实时字幕、多人分离 |
| 文字与语音查找 | 关键词加本地语义检索，返回原文、日期和播放入口；不生成跨笔记答案 |
| 快捷动作 | 两端各有“记一下”“找一下”；锁屏按系统实测，不承诺免解锁 |
| 可选云端整理 | 单条记录的标题、要点、事项候选，无自动上传或后台批量整理 |
| 系统日历 | 手动添加始终可用，云端可提供候选；用户核对保存 |
| 基础管理 | 时间线、收藏、编辑、删除、手动追加；无复杂文件夹或自动关联 |
| 数据可带走 | 可读文本和音频导出、版本化备份恢复；无账号和自动同步 |

不做会议平台、自由聊天、知识图谱、自动周报、多模型管理、付费与运营系统。未整理记录用正文开头作显示标题，不伪装成 AI 结果。

首版不建设通用自然语言日期解析器。用户在日期选择器核对具体日期、时段、时长与提醒；云端只提取事项和原始时间表达，不用模型时间戳直接写入日历。若增加相对日期快捷建议，以记录时刻和时区做确定性计算。离线状态也能手动安排日历。

## 3. 页面、视觉与动效

三个主要页面：时间线首页、查找页、记录详情；设置为次级入口，录音为底部面板。无需登录、首页仪表盘或独立 AI 标签页。

静态方向草图见 [SVG](ui-direction.svg) / [PNG 预览](ui-direction.png)。它说明布局与配色，不是可交互原型或已实现界面。

| 界面 | 布局与操作 |
| --- | --- |
| 首页 | 名称与设置；按日期排列记录；底部拇指区“记一下”“找一下”，录音为主按钮，文字输入为可见次级按钮 |
| 录音面板 | 正在录音、真实时长和音量、停止保存；取消明确丢弃，导航不默默丢录音 |
| 查找页 | 文字框和语音查询；转写可改；可见日期筛选；结果显示正文片段、日期和播放入口 |
| 详情 | 标题、时间、正文、音频；编辑、追加、主动整理、加入日历；删除在更多菜单 |
| 设置 | 模型状态与空间、云端整理、导出恢复、隐私；高级设置配置密钥 |

记录流程：快捷动作 → 录音 → 停止 → 落盘成功即反馈 → 异步转写。权限或下载只阻塞对应能力，不阻塞文字记录。

查找流程：快捷动作 → 语音查询 → 显示可修改文本 → 返回记录。查询不成为笔记，临时查询音频在完成、取消、失败及下次启动时清理。

整理流程：点击整理 → 展示发送文本与服务商 → 用户发送 → 独立结果，不覆盖正文。禁止重复点击，超时由用户选择重试并提示可能重复计费。

日历流程：手动添加或选择候选 → 核对具体日期与提醒 → 系统编辑页 → 保存、取消或未知状态。

视觉要求：图标和 UI 设计、实现必须使用 frontend-design:frontend-design 技能，按“简洁、专业、参考 ChatGPT 中性主题”的要求执行；此前青绿色方案已被取代。以黑白灰、清楚的文字层级、留白和克制的对比建立秩序，保持产品原创标识。ChatGPT 可配置强调色，本项目选择中性方向，不声称以下色值是官方设计 token。

设计 token 起点：浅色背景 #FFFFFF、次级表面 #F7F7F8、主文字/主按钮 #171717、次级文字 #666666、边界 #E5E5E5、反色文字 #FFFFFF；深色背景 #212121、次级表面 #303030、主文字/主按钮 #F5F5F5、次级文字 #B4B4B4、边界 #4A4A4A、反色文字 #171717。错误等语义色仅表达状态，不作为装饰。使用系统中文无衬线字体，标题 24–28、正文 16–17、辅助 13–14 作为初值并支持缩放。时间线左对齐，减少无意义的卡片、边框和阴影。

应用图标采用原创的语音记录意象，例如声波融入便笺；黑白均可识别，不使用 OpenAI 标志或让用户误认为官方产品。设计范围包括应用启动图标与界面操作图标，验证 iOS 图标、Android 自适应/单色图标及小尺寸辨识度。界面图标统一圆角线条，麦克风、搜索、播放、日历配标签或无障碍名称。先形成颜色、字体、布局、图标和动效 token，再对照需求审查，落地后截图检查两端浅/深色与真实交互，不用静态草图代替运行验证。

动效仅用于按下、录音状态、面板与卡片过渡，120–220ms 为调试起点而非平台标准；支持减少动态效果。音量动画不得伪装采集成功。Android 触控区域至少 48dp、iOS 至少 44pt；检查字体放大、屏幕阅读与颜色对比，状态不只靠颜色表达。

空列表引导记录；无结果可改查询、清日期；拒绝权限提供文字；静音不生成虚假正文；保存失败保留可恢复内容；模型损坏可重下；云端失败不影响离线记录。

## 4. 技术与模块边界

一个 Flutter 应用，以本机 SQLite 和私有音频文件为数据来源。UI → 页面状态与操作 → 存储、任务和系统适配；无业务服务端、微服务或通用 Agent 框架。

| 职责 | 推荐候选 | 验证重点 |
| --- | --- | --- |
| UI/状态 | Flutter/Dart，页面 ViewModel 与 SDK Listenable/ChangeNotifier | 生命周期与可访问性，不为少量页面增加状态框架 |
| 存储 | SQLite，优先评估 Drift 类型化访问与迁移；音频为私有文件 | 迁移、恢复、文件与元数据一致性 |
| 录音 | Flutter 插件及必要 Swift/Kotlin 小范围适配 | 来电、路由、锁屏、后台和权限 |
| ASR | SenseVoiceSmall INT8 + sherpa-onnx | 术语、数字、静音、改口、线程及双端打包 |
| 语义检索 | BGE-small-zh-v1.5 的 ONNX 候选 | tokenizer、pooling、归一化、转换一致性、许可和内存 |
| 云端整理 | 固定 DeepSeek 官方 API，候选 deepseek-flash 非思考模式 | 当前标识与条款、JSON 校验、限流和无效 Key |
| 日历 | iOS 系统事件编辑器，Android 插入 Intent | 保存/取消/未知、提醒字段、无日历应用 |
| 凭证 | Keychain / Keystore 支持的安全存储 | 清除、重装和恢复；排除导出与备份 |

以上未在本仓库集成。阶段 0 锁定 SDK、插件、模型与运行时版本及许可；ASR 和向量推理检查重复 ONNX 依赖、符号冲突和包体，先验证 CPU 路径。

只在实际外部边界建立接口：RecordRepository、Transcriber、SearchIndex、Organizer、CalendarBridge，各一套首版实现。不做插件市场或通用模型平台；以后能替换模型和增加本地整理，现在不建设未使用的实现。

检索以当前正文和追加内容为准，融合精确匹配与语义排序；日期过滤显式可见。约 1,000 条短记录先本地向量扫描，不引入向量数据库；中文关键词先采用归一化与子串匹配验证，规模或效果不足时升级索引。语义模型未就绪时仍可关键词搜索。命中追加内容时可返回父记录，保留每次来源和时间。

推理在工作线程，禁止阻塞 UI；ASR 与向量任务串行，新查询优先于后台索引。录音优先，不等待模型或队列；内存压力下释放空闲模型。下载与校验流式处理，不将整个模型载入 Dart 内存。

## 5. 数据与恢复

| 对象 | 最少信息和约束 |
| --- | --- |
| 记录 | ID、创建时刻/时区、来源、正文、修订号、音频引用、收藏、可选父记录 ID |
| 原始转写 | 所属音频、识别结果与模型版本；用户修改另存正文 |
| 派生结果 | 来源 ID/修订号、标题/要点/事项、模型；正文改变则标过期 |
| 本地任务 | 来源 ID/修订号、类型、状态、失败原因；写回验证存在和版本一致 |
| 索引 | 来源 ID/修订号、embedding 版本；可重建，不是唯一数据来源 |
| 日历尝试 | 来源候选、发送字段、保存/取消/未知；未知不能自动重试插入 |

录音停止先关闭并验证文件，再提交元数据，成功才反馈。临时文件与恢复标记配合启动修复，检查有效片段、孤儿文件和缺失引用；提示中断，不承诺进程被杀时全部音频无损。保存、转写、整理与索引状态分开。

本地任务默认前台处理、持久化状态，下次启动恢复，不承诺后台任意时长执行。云端中断不自动重放。旧任务不得覆盖用户新正文，删除取消任务并清理文件和索引。追加为独立记录关联父记录；删除父记录默认整组删除，确认界面说明数量。

日历只创建一次性事件，不读取整个日历。iOS 收到可靠 saved 回调才标成功；Android 无可靠回执时展示保存未确认。笔记编辑/删除不改变已经创建的系统事件。

备份包含版本化元数据、可读文本和音频，排除模型和密钥。先校验格式、路径、大小和引用，拒绝路径穿越及不支持版本，在暂存区通过验证后合并。相同 ID/内容跳过，不同内容保留冲突副本并重映射关联；索引重建。导出明示未加密与保存位置。

## 6. 安全

- 联网仅用于主动模型下载和确认后的整理；音频、查询、笔记库默认不外发，无内容分析 SDK。
- 固定服务商域名与 HTTPS，无任意 Base URL，不向重定向目标发送 Authorization；Key 不进日志、崩溃报告、备份或 Git。
- BYOK 仍有设备受损、服务商留存与费用风险；明确供应商和发送文本，可清除凭证和停用，不因“不训练”宣称“不留存”。
- 单条选中正文才可发送；建议初始上限 8,000 字符、短输出、30 秒超时，失败均由用户主动重试。
- 模型输出不可信：校验空响应、JSON、字段、长度和文本依据；不执行命令、工具调用、自动日历写入或模型给出的操作指令。
- 默认排除内容和模型的自动云备份，核验平台实际行为；导出云盘与同步日历说明内容离开设备的边界。
- 模型清单固定版本、可信来源与 SHA-256；临时下载校验后原子切换，空间不足保留原版本。散列不能替代清单可信来源。

## 7. 验收与性能预算

在两台手机记录实际 OS、内存配置、模型、运行时与冷/热状态。以下为建议目标，不是已有结果；未达标时报告并调整实现或支持范围，不静默降低门槛。

| 领域 | 建议出口条件 |
| --- | --- |
| 离线 | 飞行模式完成录音、转写、文字/语音查找、回放和编辑；网络检查无内容外发 |
| 录音 | 已授权、App 前台点击至采集 P95 ≤ 500ms，停止至保存反馈 P95 ≤ 1s；快捷入口冷启动单测 |
| 推理 | 30 秒录音转写 P95 ≤ 15s；测峰值内存、发热和连续使用，不因推理丢录音或卡 UI |
| 搜索 | 1,000 条记录、模型已加载的文字查询 P95 ≤ 1s；冷启动和查询转写分别报告 |
| 质量 | 至少 50 条口述涵盖术语、数字、否定、改口、静音、噪声；关键错误逐例评审；云端不将不确定改为确定 |
| 找回 | 至少 30 条有答案标注查询，Top-3 命中率目标 ≥ 90%；另测无答案和冲突记录，不以相似度冒充事实可信度 |
| 一致性 | 编辑/删除期间任务完成不覆盖或复活记录；中断可恢复，云端不自动重放 |
| 日历 | 两台手机各实际新增并收到提醒；覆盖取消、重复点击、未知回执、不可用日历 |
| 恢复 | 文本、音频、时间、收藏、追加关系完整；重复导入幂等，冲突可见，损坏备份不破坏原数据 |
| UI | 字体放大、深色、屏幕阅读和减少动态效果可用；错误可恢复，录音/查找无歧义 |

性能场景先采约 20 次形成基线并注明样本量，发布候选扩大样本检查长尾。调参与验收集分开，使用自愿提供的非敏感样本。模拟器和编译成功不替代真机；阶段 0 核实 iOS 签名与安装条件。

## 8. 开发顺序与交付

1. 风险验证：工具与签名；双端录音、ASR、向量推理、快捷入口和日历；锁定依赖、许可、模型分发。离线记查不可达时先解决或明确调整，不带着未验证前提铺完整 UI。
2. 可靠记录：应用壳、三页面、文字、录音、落盘、回放、编辑删除、追加和任务恢复，验证中断与一致性。
3. 离线找回：下载校验、ASR、关键词和语义检索、两个快捷动作，通过标注样本验收。
4. 安排与整理：先手动日历，再 BYOK 单条云端整理，测试鉴权失败、限流、超时、无效输出和取消。
5. 试用版本：导出恢复、动效与可访问性、网络核验、双端回归；交付可安装版本与已知限制，两周试用。

技术验证前不承诺固定工期。MVP 包含离线语音查找和手动日历，不以只有录音的演示当成完成。试用观察真实记录频次、找回成功与修订负担，不自动采集私人内容。

项目规则按已确认的 [ADR-0001](adr/0001-local-first-optional-cloud.md) 同步本地优先与可选云端边界。独立设计审阅未发现阻碍制定计划的重要信息缺口，仍不代表依赖集成、性能或产品价值已经验证。
